# EGO API surface — what works (and what doesn't)

Reverse-engineering notes for the data sources EGO Mac talks to. Generated by
poking the iOS Cep'te app over USB (`pymobiledevice3 pcap --process Runner`),
the public website, and the Aptoide-hosted Android APK
(`com.ego.android` v4.0.7, 22 MB).

The script `scripts/probe-ego.sh` rerun the probes any time EGO ships an
update.

## Hosts

| Host | Notes |
|---|---|
| `egocptsrvand.ego.gov.tr` | Mobile JSON service used by the iOS app. F5 BIG-IP fronted. Confirmed via TLS SNI in iPhone pcap. |
| `www.ego.gov.tr` | Public website. Has a few useful Ajax endpoints. |
| `m.ego.gov.tr` | Mobile-targeted public website. Identical payloads as `www.`; keep `www.` to avoid `410 Gone` on legacy paths. |

## ✅ Confirmed working endpoints

### 1. `mblSrv14/service.asp?FNC=Otobusler&DURAK={stopNo}`

Lists every line currently active at a stop. One row per line: a live bus when
one exists, otherwise a scheduled-departure row.

```bash
curl -ks "https://egocptsrvand.ego.gov.tr/mblSrv14/service.asp?FNC=Otobusler&VER=3.1.0&LAN=tr&DURAK=10940" \
     -A "EGO Cepte/8 CFNetwork/1568.300.101 Darwin/24.0.0"
```

Sample response shape: see `Sources/EGOMac/EGOClient.swift` `EGORow`.
Live rows have `plaka_no`, `lat`, `lng`, `saniye`. Scheduled rows have
`arac_no="-"` and a single `sure` text.

### 2. `mblSrv14/service.asp?FNC=Otobus&HAT={lineCode}&DURAK={stopNo}`

Every live bus on `lineCode`, with ETA computed against `stopNo`. Sorted by
`saniye` ascending. Past buses come back as `saniye=999999` and `sure="Geçti"`.

```bash
curl -ks "https://egocptsrvand.ego.gov.tr/mblSrv14/service.asp?FNC=Otobus&VER=3.1.0&LAN=tr&HAT=481&DURAK=10940" \
     -A "EGO Cepte/8 CFNetwork/1568.300.101 Darwin/24.0.0"
```

### 3. `https://www.ego.gov.tr/AjaxData/HatListesi` — POST

Returns the complete bus-line list as a single `<option>` blob (~55 KB).
`hat_no` is optional and filters; omit it to get every line.

```bash
curl -ks -X POST "https://www.ego.gov.tr/AjaxData/HatListesi" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -H "X-Requested-With: XMLHttpRequest" \
     -H "Referer: https://www.ego.gov.tr/hareketsaatleri" \
     --data "hat_no=481"
```

Each option looks like:

```
<option value="481"> (481 ) - UYANIŞ-ASFALT-15 TEMMUZ KIZILAY MİLLİ İRADE MEYDANI-BALGAT-CEYHUN A.K.CAD</option>
```

Companion endpoints (same payload pattern, different mode):

- `/AjaxData/HatListesiOtobus` — bus only
- `/AjaxData/HatListesiMetro` — metro only
- `/AjaxData/HatListesiAnkaray` — ankaray only

### 4. `https://www.ego.gov.tr/HareketSaatleri` — POST `hat_no1={lineCode}`

Returns the full schedule page (~80 KB) for a line. Includes:

- Hat No, Hat Adı, Kalkış Yeri, Varış Yeri, Mesafesi (km), Süresi (dakika)
- Three columns of departure times: **Hafta içi**, **Cumartesi**, **Pazar**
- Notes against specific times (e.g. `06:17 21071DEN BAŞLAR /KARAPINARDAN 06:50`)

```bash
curl -ks -X POST "https://www.ego.gov.tr/HareketSaatleri" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     --data "hat_no1=481"
```

The schedule lives between `<!-- Saat Tablosu -->` and the next `</div>`, with
the three-column header literally `<th>Hafta içi</th><th>Cumartesi</th><th>Pazar</th>`.

### 5. Embedded local stops blob (`Sources/EGOMac/StopsBlob.swift`)

Already shipped: 2 943 stops with `stopNo`, `name`, `lat`, `lng`. Powers
`SearchIndex.swift`. No network needed.

## ❌ Endpoints found in the APK but **dead** on the live server

The Android APK (`lib/x86_64/libapp.so`, Flutter compiled Dart) references
these paths, but every one returns `200 OK` with `Content-Length: 0` against
`egocptsrvand.ego.gov.tr` (and `410 Gone` against `m.ego.gov.tr`):

```

/hibrit/action.asp?FNC=AnkaraKartBayiler
/hibrit/action.asp?FNC=AnkaraKartBayilerYakin
/hibrit/action.asp?FNC=AnkaraKartKullanim&KART=
/hibrit/action.asp?FNC=Durak&KOD=
/hibrit/action.asp?FNC=Duraklar&QUERY=
/hibrit/action.asp?FNC=DuraklardanGecisSaatleri&HAT=
/hibrit/action.asp?FNC=DuraktanGecenHatlar&KOD=
/hibrit/action.asp?FNC=DuraktanGecisSaatleri&HAT=
/hibrit/action.asp?FNC=Duyurular
/hibrit/action.asp?FNC=HatAra&QUERY=
/hibrit/action.asp?FNC=YakinDuraklar&MSF=
/hibrit/act.asp?FNC=Hat&KOD=
/hibrit/act.asp?FNC=HatBilgileri&YOL=TRUE&KOD=
/hibrit/act.asp?FNC=Hatlar&QUERY=
/hibrit/srv.asp?LAN=tr&FNC=Otobus&DURAK=
/hibrit/srv.asp?LAN=tr&FNC=Otobusler&DURAK=

/hibrit/connect/androidConn.asp
/hibrit/duyuru.asp?FNC=Duyuru&ID=
/hibrit/ankarakartdolum.asp
/hibrit/mavimasa.asp
```

POST, header tweaks, `deviceId` headers, and varying `VER` parameters all hit
the same wall. Possible explanations:

- The APK we have (4.0.7) is older than the live iOS app (User-Agent v8). The
  iOS app may have moved to a different host or auth flow we haven't sniffed.
- Auth/session is required and the Connect endpoints need a body shape we
  haven't reverse-engineered.
- Server-side feature gate keyed off some header we're missing.

These are documented for future reference. Until we crack them, the live app
gets:

- ✅ Stop search → embedded blob
- ❌ Stop search via server (would let us discover stops added after release)
- ✅ Line list, line metadata, line schedules → website endpoints
- ❌ Ordered list of stops on a line, with names and coords (the website only
  lists schedule times, not the stop sequence)

## Workaround for "ordered stops on a line"

Without a direct endpoint we approximate by sampling: every `FNC=Otobus&HAT=X`
response includes `durak_no` and `onceki_durak_no` for each live bus. Repeated
polls accumulate `(durak_sira_no → durak_no)` mappings; cross-referencing with
the embedded `StopsBlob` recovers the stop name and coords. Stops at sequence
numbers no live bus has ever passed remain unknown until an actual bus rides
through them.

This is implemented in `Sources/EGOMac/RouteIndex.swift`
(`recordPositions(forLine:from:)`), persisted under `~/.ego-mac/route-cache/`.

## User-Agent

The iOS app pcap shows:

```
User-Agent: EGO Cepte/8 CFNetwork/1568.300.101 Darwin/24.0.0
```

We send the same string. The Android APK uses Dart's `dart:io` default UA
(`Dart/3.5 (dart:io)`). Either is accepted by the working endpoints.
